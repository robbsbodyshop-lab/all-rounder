# Code hosts and registries: physician-built specialty AI assistants on Grok Bot / OpenMausBot (literal reading) and on the OpenClaw family (fallback reading)

Research date: 15 November 2026. All star counts, fork counts and created/pushed dates below are from the GitHub search API as returned on 15 Nov 2026 unless stated otherwise. "Verified" means I opened the page, file or API record myself in this session; "unverified" means I could not open a source that confirms it. Match grades use the brief's three criteria: (a) verifiable physician author, (b) specialty-specific or tied to the physician's own clinical/academic work, (c) built on / packaged for the framework.

How the search was done (so the writer can judge coverage): about 1,090 GitHub repository-search API queries in total — ~150 README-level queries for `openclaw`/`clawdbot` x specialty and clinician terms, ~200 name/description/topic-level queries for `moltbot`, `clawdbot`, `nanoclaw`, `zeroclaw`, `picoclaw`, `ironclaw`, `nemoclaw`, `nanobot`, `hermes-agent` and OpenClaw topics, ~460 queries for `openmausbot`, `mausbot`, `"grok bot"`, `grokbot` x ~75 specialty/clinician terms (README-level; 138 of them fork-only), ~140 for `opengrokbot`, `rakazo`, `"x.ai/bot"`, Grok Bot skills/templates and Grok Bot topics, and 132 date-sliced queries that enumerated 3,262 forks of OpenMausBot and its sibling repos; the ClawHub registry search API (79 medical terms, 655 distinct listings); two machine-readable catalogs of shared Grok Bot templates (7,858 and 4,933 entries), the botdirectory.ai feed (883 bots) and the grokbot.dev feeds (1,904 templates, 60 plugins, 138 use cases); raw READMEs of ~60 candidate repos; GitHub profile pages; one ORCID record; quick probes of Hugging Face, GitLab, Codeberg and npm.

## Which framework do the garbled names refer to: is "Grok Bot / OpenMausBot" literal, and what is the OpenClaw naming history? (verification requested by coordinator)

### Takeaway
Both readings point at real products. "Grok Bot" (xAI, announced 11 Aug 2026) and "OpenMausBot" (github.com/milind-soni/OpenMausBot, created the same day, ~23.3k stars, ~3.2k forks, Apache-2.0, "with a virtual machine that bots can use") exist exactly as named, so the literal reading is the better fit for "Grok Bot / OpenMausBot-style VM agent framework"; OpenClaw (ex-Clawdbot, ex-Moltbot) is a separate, older project and is kept here only as a fallback.

### Cited Findings
- xAI's announcement is dated 11 August 2026 and says "Grok Bot is your team of always-on agents"; the bots "have their own computer, work inside tools and apps like you do"; beta for SuperGrok tiers and some Cursor plans; the site navigation has a Marketplace page — [x.ai: Introducing Grok Bot](https://x.ai/news/introducing-grok-bot)

### Inferences
- A physician dictating "Grok Bot / OpenMausBot-style VM agent framework" is far more likely to mean xAI Grok Bot and its open-source clone OpenMausBot than OpenClaw: both names match exactly, and OpenMausBot's own tagline is about the "virtual machine that bots can use".
- Anything built on Grok Bot or OpenMausBot can be at most ~3 months old (11 Aug to 15 Nov 2026), which limits how mature or well-documented a physician-built specialty assistant could be on code hosts.
- On Grok Bot the natural "artifact" is a shared bot link (x.ai/bot/<id>) or Marketplace listing, not a GitHub repo; on OpenMausBot it is a Markdown team playbook or an exported backup JSON. Code-host search therefore under-samples this ecosystem.

### Gaps
- I could not confirm from the OpenMausBot README that the project was "formerly OpenGrokBot"; the README I read does not say so.
- I did not verify xAI's Marketplace submission rules or whether share pages show the sharer's verified identity.
